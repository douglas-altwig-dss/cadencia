# Internationalisation

Cadência speaks **English (US)** (`en-US`, the default), **Brazilian Portuguese** (`pt-BR`) and
**German** (`de-DE`). This file is the contract every change follows.

## Decisions

- **Default is `en-US`, always.** No auto-detection from the browser. A person picks a language in
  the preferences menu (header, gear icon); the choice is per browser (`localStorage`
  `cadencia-locale`) and never travels to the server except as the request language.
- **What is translated:** everything a person reads in the web app, including text the API sends
  (errors' `cause`/`action`/`message`, validation problems, risk evidence, health problems, epic-plan
  problems, field catalogue labels, notification text).
- **What is not translated:**
  - The generated deck (.pptx) and its content stay as they are today (pt-BR values). The deck is a
    corporate artefact filled into a pt-BR template; its language is a separate decision.
  - Jira data (status names, issue titles, people) — shown as Jira sends it.
  - URLs and route paths (`/pessoas`, `/apresentacao`, `?tab=` values), `localStorage` keys, JSON
    keys on the wire (the planning contract is Portuguese on purpose), CLI JSON keys.
  - Code, identifiers and comments stay English, as before.
- **Request language:** the web client sends `Accept-Language: <locale>` (the chosen one, exactly)
  on every API call. The backend answers in that language when supported, else `en-US`. Anything
  produced outside a request (scheduler notifications, CLI) uses `CADENCIA_LOCALE` (default `en-US`).
- **German uses the formal "Sie"**, sentence case, and Jira's own German vocabulary where Jira has one.
- Translations are written by hand per locale (no machine fallback at runtime). A missing key is a
  type error, not a runtime blank.

## Frontend mechanics (`web/src/i18n/`)

- `locales/en-US/<namespace>.ts` is the source of truth; its exported object's type *is* the shape.
  `pt-BR/` and `de-DE/` export objects typed against it, so a missing or extra key fails `npm run typecheck`.
- Values are strings, or functions for anything with parameters or plurals:
  `blocks: (n: number) => plural(n, 'block', 'blocks')`. Never concatenate translated fragments in
  a component: word order differs between the three languages — give the whole sentence a function.
- Components: `const t = useT();` then `t.people.title`, `t.people.blocks(3)`.
  Outside React (lib code, constants): `t()` returns the current catalogue — call it **at use time**,
  never at module load (a module-level constant would freeze the first language).
- Dates and numbers go through `lib/format.ts`, which follows the current locale.
  Sorting people/names uses `collator()` / `currentLocale()` from `i18n`, not a hard-coded `'pt-BR'`.
- Changing the language remounts the app (`key={locale}`) and resets the query cache, because API
  responses carry translated text.
- Keep the project's copy rules in every language: no "item(s)"-style text (use plural functions),
  sentence case, state never told by colour alone, People copy describes facts, never judges.

## Backend mechanics (`backend/cadencia/i18n/`)

Design, inventory and task split: [`docs/i18n-backend.md`](i18n-backend.md).

- Catalogues are `cadencia/i18n/locales/<en_US|pt_BR|de_DE>/<namespace>.py`, each exporting
  `MESSAGES` (`str` with `{named}` fields, or a callable taking the params). Namespaces are found by
  `pkgutil`: add three files, edit no registry. `tests/test_i18n.py` checks keys, parameters,
  rendering and every key the code uses. `tools/i18n_scan.py <paths>` lists pt-BR literals left.
- Pure code (`domain/`, `report/core/`) only builds messages and imports `cadencia.i18n.message`:
  `raise Invalid(Msg("epic_plan.limit", low=1, high=600))`. Boundaries render in the ambient
  locale (request, else `CADENCIA_LOCALE`, pt-BR while the deck's data is built):
  `tr("common.error.invalid")`, `render(msg)`, and `return localize(view)` for a tree holding `Msg`s.
- Stored text: `{"$msg": …}` via `msg.to_json()` plus a pt-BR mirror; read with `stored_text(record, legacy)`.

## How to translate a screen

1. Add the keys to your namespace in `web/src/i18n/locales/en-US/<namespace>.ts`, then the same keys in
   `pt-BR/` and `de-DE/` (`npm run typecheck` lists whatever is missing or extra). Only you edit your namespace.
2. In a component: `import { useT } from '../i18n';` (adjust the `../`) and `const t = useT();`.
   Outside React: `import { t, plural, collator, currentLocale } from '../i18n';` and call `t()` inside the function.
3. Replace each literal. From `components/HeaderTools.tsx`'s `PreferencesMenu`:

   ```tsx
   // before                                   // after
   <Text size="xs" fw={600}>Tema</Text>         <Text size="xs" fw={600}>{t.shell.preferences.theme}</Text>
   { value: 'light', label: 'Claro' },          { value: 'light', label: t.shell.preferences.themeLight },
   ```

   With parameters, the catalogue holds a function: `blocks: (n: number) => plural(n, 'block', 'blocks')`.
4. Run `npm run i18n:scan -- <path>` on the files you own (files or folders, e.g. `src/components/people`);
   add `--strict` to get exit code 1 while anything is left. It is a heuristic: read what it lists.
